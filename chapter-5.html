Правило эксперимента

Меняйте одну вещь за раз. Зафиксируйте seed, разделение данных и число шагов. Иначе невозможно понять, что именно улучшило результат: архитектура, оптимизатор или случайность.

Реализация: базис, слой, модель

Начнём с базиса. Функция принимает тензор входов произвольной формы (..., n_in) и возвращает значения всех базисных функций: (..., n_in, G+k). Внутри — та же рекурсия Кокса–де Бура, что в главе 4, но векторизованная по точкам.

basis.py — ядро B-сплайнов 
def forward(self, x):
    t, k, m = self.knots, self.degree, self.knots.numel()
    shape = x.shape
    xf = x.reshape(-1)

    # степень 0: индикаторы интервалов
    B = ((xf[:, None] >= t[None, :-1]) &
         (xf[:, None] <  t[None, 1:])).to(x.dtype)
    at_right = torch.isclose(xf, t[-1])
    if at_right.any():
        B[at_right, m - k - 2] = 1.0

    # рекурсия Кокса–де Бура
    for d in range(1, k + 1):
        den1 = t[d:m - 1] - t[:m - d - 1]
        den2 = t[d + 1:m] - t[1:m - d]
        c1 = (xf[:, None] - t[None, :m - d - 1]) / den1.clamp_min(1e-12)
        c2 = (t[None, d + 1:m] - xf[:, None]) / den2.clamp_min(1e-12)
        c1 = torch.where(den1 > 1e-12, c1, torch.zeros_like(c1))
        c2 = torch.where(den2 > 1e-12, c2, torch.zeros_like(c2))
        B = c1 * B[:, :m - d - 1] + c2 * B[:, 1:m - d]

    return B.clamp_min(0.0).reshape(*shape, self.n_basis)

Тонкость — правый конец отрезка. По соглашению [ti, ti+1) точка x = 1 не попадает ни в один интервал нулевой степени, поэтому её вручную относят к последнему ненулевому интервалу. Без этого базис в точке 1 обнулился бы и нарушил разбиение единицы.

Теперь слой. Он хранит коэффициенты формы (nout, nin, G+k) и базовые веса (nout, nin). Прямой проход — это два тензорных произведения.

layer.py — слой KAN 
class KANLayer(nn.Module):
    def __init__(self, n_in, n_out, grid_size=5, degree=3):
        super().__init__()
        self.basis = BSplineBasis(grid_size, degree)
        self.coef = nn.Parameter(torch.empty(n_out, n_in, self.basis.n_basis))
        nn.init.normal_(self.coef, mean=0.0, std=0.1)
        self.base_weight = nn.Parameter(torch.ones(n_out, n_in))
        self.bias = nn.Parameter(torch.zeros(n_out))
        self.scale = 1.0 / math.sqrt(n_in)

    def forward(self, x):
        basis = self.basis(x)                          # (B, n_in, G+k)
        spline = torch.einsum("bik,oik->bo", basis, self.coef)
        base = F.silu(x) @ self.base_weight.T           # (B, n_out)
        return (base + spline) * self.scale + self.bias

Запись einsum("bik,oik->bo") читается так: для каждого примера b и каждого выхода o просуммировать по входу i и базису k произведение basis[b,i,k] * coef[o,i,k]. Это ровно Σi Σk coikBk(xbi).

Модель — просто список слоёв. Масштаб 1/√nin удерживает дисперсию сигнала примерно постоянной при переходе между слоями — тот же принцип, что в инициализации Xavier/He.

model.py — композиция слоёв 
class KAN(nn.Module):
    def __init__(self, widths, grid_size=5, degree=3):
        super().__init__()
        self.layers = nn.ModuleList(
            KANLayer(widths[i], widths[i + 1], grid_size, degree)
            for i in range(len(widths) - 1)
        )

    def forward(self, x):
        for layer in self.layers:
            x = layer(x)
        return x

Эксперимент 1: одномерная функция

Первая задача — f(x) = sin(πx) на [−1, 1]. Сеть 1 → 1 при G = 5, k = 3 содержит всего 10 параметров: 8 коэффициентов сплайна, базовый вес и смещение.

В версии без зависимостей коэффициенты обучаются аналитическими градиентами. Для MSE производная по коэффициенту сплайна выглядит так:

∂L∂ck = 2N Σi (ŷi − yi) Bk(xi)
Градиент по коэффициенту сплайна. Базис играет роль «входа» линейной модели.

Почему это линейная задача

При фиксированном базисе сплайн линеен по коэффициентам c. Поэтому для одного слоя 1 → 1 обучение — это обычная линейная регрессия с базисом из B-сплайнов. Вся сложность KAN появляется, когда слоёв несколько и функции входят друг в друга.

Не гонитесь за последней цифрой

На игрушечной задаче легко получить почти нулевую ошибку и решить, что метод «решает всё». Проверяйте обобщение на отдельной выборке и смотрите на форму выученной функции, а не только на MSE.

Сравнение с MLP: как не обмануть себя

Сравнивать архитектуры «по числу параметров» или «по числу шагов» — недостаточно. Честный протокол фиксирует несколько вещей одновременно.

  • Одинаковые данные и splits. Один и тот же train/val/test, один и тот же seed (или несколько seed).
  • Сопоставимый бюджет. Либо равное число параметров, либо равное время обучения, либо равное число шагов. Нельзя сравнивать «KAN за 5000 шагов» с «MLP за 500».
  • Одинаковая настройка. Хотя бы грубый подбор learning rate для обеих моделей.
  • Несколько запусков. Разброс по seed часто больше, чем разница между архитектурами на игрушечной задаче.

В оригинальной работе Лю и др. (2024) показали, что на гладких игрушечных функциях KAN масштабируется лучше MLP: ошибка падает быстрее при росте числа параметров. Это сильный результат, но он относится к задачам определённого типа.

Независимое сравнение Yu et al. («KAN or MLP: A Fairer Comparison», 2024) даёт более сдержанную картину: на компьютерном зрении, обработке языка и аудио MLP обычно выигрывает по точности и существенно — по скорости; KAN лучше в символьном представлении формул и непрерывном обучении. Это важный противовес хайпу.

Что нельзя утверждать

«KAN лучше MLP» и «KAN хуже MLP» — одинаково неверные обобщения. Корректная формулировка звучит так: на таких-то данных, при таком-то бюджете и такой-то настройке KAN дал такую-то ошибку за такое-то время. Всё остальное — маркетинг.

Интерпретируемость на практике

Начнём с разреживания. Добавим к MSE штраф на абсолютные величины коэффициентов сплайнов:

sparsity.py — L1-регуляризация 
mse = F.mse_loss(model(x), y)

# штрафуем только коэффициенты сплайнов (тензоры размерности 3)
l1 = sum(p.abs().mean() for p in model.parameters() if p.ndim == 3)
loss = mse + 1e-2 * l1

После обучения оценим важность рёбер. Простая мера — средний модуль коэффициентов ребра:

prune.py — важность и удаление рёбер 
with torch.no_grad():
    layer = model.layers[0]
    importance = layer.coef.abs().mean(dim=2)      # (n_out, n_in)

    threshold = torch.quantile(importance, 0.5)    # оставить половину
    mask = (importance >= threshold).float()

    # обнуляем коэффициенты и базовые веса отрезанных рёбер
    layer.coef.mul_(mask[..., None])
    layer.base_weight.mul_(mask)

Затем каждое оставшееся ребро можно попробовать заменить простой формулой. В kan_torch.py есть функция symbolic_fit_1d: она перебирает кандидатов (x, x2, x3, sin, cos, tanh, exp, |x|), масштабы b и подбирает линейные a, d методом наименьших квадратов.

symbolic.py — суть подгонки 
for name, fn in candidates.items():
    for b in torch.linspace(0.5, 4.0, 36):
        z = fn(b * x)                       # кандидат
        A = torch.stack([z, torch.ones_like(z)], dim=1)
        sol = torch.linalg.lstsq(A, y.unsqueeze(1)).solution
        error = torch.mean((A @ sol - y.unsqueeze(1)) ** 2)
        # запоминаем лучшую пару (name, b, a, d)

На задаче sin(πx) этот перебор должен вернуть что-то вроде 1.0 · sin(3.14 x) + 0.0. Совпадение масштаба b с π — хороший признак того, что сеть выучила именно синус, а не просто похожую кривую.

Пример из статьи

Для функции exp(sin(πx) + y2) KAN восстановил внутренние рёбра sin и y2, а внешнее — экспоненту. Именно такие примеры показывают, зачем нужна интерпретируемость: модель не просто предсказывает, а предлагает структуру зависимости.

Уточнение сетки и двумерный пример

Вернёмся к grid extension. В коде это отдельный метод модели. Он запоминает старую функцию, строит новый базис и решает МНК для каждого ребра:

extend.py — уточнение без переобучения 
@torch.no_grad()
def extend_grid(self, new_grid_size):
    for layer in self.layers:
        old = layer.basis
        xs = torch.linspace(old.lo, old.hi, 256)

        old_basis = old(xs)                              # (S, n_in, nb_old)
        values = torch.einsum("sik,oik->soi", old_basis, layer.coef)

        new_basis = BSplineBasis(new_grid_size, old.degree)
        new_B = new_basis(xs)                            # (S, n_in, nb_new)

        A = new_B.permute(1, 0, 2)                       # (n_in, S, nb_new)
        Y = values.permute(2, 0, 1)                       # (n_in, S, n_out)
        solution = torch.linalg.lstsq(A, Y).solution

        layer.coef = nn.Parameter(solution.permute(2, 0, 1))
        layer.basis = new_basis

Важно: после замены коэффициентов нужно создать новый оптимизатор — старый хранит ссылки на прежние параметры. В нашем скрипте train() создаёт Adam заново, поэтому последовательность «обучить → расширить → обучить» работает корректно.

Стандартизация цели

Для регрессии полезно вычесть среднее и поделить на стандартное отклонение y, а на выходе вернуть масштаб обратно. Это не меняет задачу, но делает скорость обучения и пороги ошибки сопоставимыми между задачами. Для KAN это особенно удобно: сплайны работают с входами в [−1, 1], и выходной масштаб тоже лучше держать разумным.

Экстраполяция

Сплайн определён на [−1, 1]. За пределами этого отрезка базисные функции равны нулю, и остаётся только wbSiLU(x) — то есть линейный хвост. Не ждите от KAN разумного поведения вне обучающего диапазона; это принципиальное ограничение выбранного базиса, а не ошибка обучения.

  6. Сформулируйте протокол честного сравнения KAN и MLP на вашей задаче. Какие величины вы зафиксируете и какие будете измерять?
  7. Объясните, почему KAN медленнее MLP при том же числе параметров, и почему он всё равно может быть выгоден.
Ответы и комментарии
  1. Ошибка вырастет: восьми базисных функций на два периода синуса не хватает. Увеличение G добавляет локальные степени свободы, и ошибка падает. Это прямая иллюстрация компромисса «разрешение сетки против числа параметров». На проверке при G = 5 получается MSE ≈ 1.7·10−3, а при G = 11 — уже 1.8·10−5.
  2. KAN: 2·5·(7+3+1) + 5 = 115 и 5·1·11 + 1 = 56, итого 171. MLP: (2·5 + 5) + (5·1 + 1) = 21. Отношение ≈ 8.1×.
  3. С L1 коэффициенты стремятся к нулю, часть рёбер «схлопывается». Функция становится проще, но MSE может немного вырасти. Это ожидаемый обмен точности на интерпретируемость.
  4. После расширения функция должна почти не измениться — МНК подбирает коэффициенты так, чтобы сохранить значения на старой сетке. Небольшое изменение возможно из-за численных погрешностей и разного базиса.
  5. Для x³ кандидат есть в библиотеке, поэтому подгонка должна дать хороший результат. Для |x| тоже есть кандидат, но гладкий сплайн приблизит излом лишь приближённо — ошибка будет заметнее.
  6. Зафиксировать: splits, seed (лучше несколько), число шагов или время, бюджет параметров. Измерять: MSE на val/test, время обучения, время инференса, разброс по seed. Дополнительно — визуальную форму функции.
  7. Каждое ребро KAN требует вычисления G+k базисных функций и умножения на коэффициенты, тогда как MLP — одного умножения. Зато KAN может достичь той же точности меньшим числом параметров и даёт интерпретируемые рёбра.

Мини-проект

Возьмите f(x, y) = sin(πx)·cos(πy). Сравните KAN 2 → 2 → 1 (G=5) и MLP 2 → 6 → 6 → 1: у них сопоставимый бюджет параметров. Обучите каждую модель с тремя seed, измерьте MSE на отложенной выборке и время обучения. Оформите таблицу и сделайте вывод: в каких условиях выигрывает каждая архитектура.

Итоги части I

Мы прошли путь от «что такое обучение» до работающей KAN. Пять глав складываются в целостную картину:

  • Глава 1 дала язык: данные, модель, потери, оптимизация и место KAN среди нейросетей.
  • Глава 2 — математический аппарат: матрицы, градиенты, вероятность, градиентный спуск и численная устойчивость.
  • Глава 3 — MLP, backprop, обобщение и универсальная аппроксимация: база, с которой сравнивается любая новая архитектура.
  • Глава 4 — теорема Колмогорова–Арнольда, B-сплайны и точная формула слоя KAN.
  • Глава 5 — код, эксперименты, сравнение и интерпретация.

Главный вывод: KAN — это не «нейросеть будущего, которая всё заменит», а интересный класс моделей с другим индуктивным смещением. Он естественно работает там, где функция гладкая, размерность невелика, а результат нужно понять. Он проигрывает MLP в скорости и на больших неструктурированных данных. Понимание этого баланса важнее, чем любая модная архитектура.
