Реальная KAN на Iris: обучение и сохранение

Соберём KAN, которая действительно классифицирует цветы: четыре входа, три класса, 111 параметров. Обучим её на 120 примерах, проверим на 30, сохраним веса в JSON и подключим к странице, где любой человек сможет ввести измерения и получить ответ.

Нужны глава 6 (данные и метрики) и раздел 4.4 (слой KAN). Код можно просто запустить: он сам обучит модель и сохранит веса. Если хотите понять каждую строку — возвращайтесь к главам 2–5 по мере вопросов.

Архитектура: четыре входа, три класса

Для Iris мы используем один слой KAN 4 → 3. Каждый из трёх выходов (логитов) складывает четыре функции, по одной на признак:

zk(x) = Σi=14 φk,i(xi) + bk,    k = 1, 2, 3
Один слой KAN. φk,i — обучаемая функция ребра «признак i → класс k».

Каждая φk,i — это B-сплайн степени k = 3 на сетке G = 5 плюс базовая SiLU. На ребро приходится G + k = 8 коэффициентов сплайна, один базовый вес и одно смещение на выход. Итого:

P = 3 · 4 · (8 + 1) + 3 = 111
Число параметров. Три класса, четыре признака, девять параметров на ребро плюс смещения.

Почему один слой, а не глубокая сеть? Для четырёх признаков и трёх классов этого достаточно: модель получается компактной, быстрой и интерпретируемой. Если бы понадобились взаимодействия «признак × признак», мы бы добавили скрытый слой или признаки-произведения. Но начинать всегда стоит с простого.

От логитов к вероятностям

Логиты zk — произвольные числа. Чтобы получить вероятности, применяем softmax, а качество измеряем кросс-энтропией:

pk = exp(zk)Σj exp(zj),    L = − log py
Softmax и кросс-энтропия. y — индекс правильного класса.

Градиент по логитам удивительно простой: это разность предсказанной вероятности и «единички» правильного класса.

δk = pk − 1[k = y]
Сигнал ошибки. Для правильного класса отрицательный, для остальных — положительный.

Дальше градиенты каждого параметра получаются умножением δk на вход соответствующего ребра. Для коэффициента сплайна, базового веса и смещения:

∂L∂ck,i,b = δk Bb(xi),    ∂L∂wk,i = δk SiLU(xi),    ∂L∂bk = δk
Градиенты одного слоя. Всё усредняется по батчу.

Обратите внимание: при фиксированных данных и базисе логиты линейны по коэффициентам. Значит, один слой KAN с softmax — почти линейная классификация в признаковом пространстве B-сплайнов. Это делает обучение устойчивым и быстрым, но ограничивает взаимодействия между признаками. Для Iris этого хватает; для более сложных данных нужен второй слой.

forward_backward.py — ядро обучения 
for basis, base_vals, y in zip(S, Bv, Y):
    p = softmax(logits(basis, base_vals))

    for k in range(3):
        d = (p[k] - (1.0 if k == y else 0.0)) / N

        grad_bias[k] += d
        for i in range(4):
            grad_base[k][i] += d * base_vals[i]
            for b in range(8):
                grad_coef[k][i][b] += d * basis[i][b]

Обучение и результаты

Данные делим стратифицированно: 120 примеров в обучение, 30 — в отложенную выборку. Min/max считаем только по 120. Входы переводим в [−1, 1], метки — в индексы 0, 1, 2. Оптимизатор — Adam с η = 0.02, полный батч, 3000 шагов, кросс-энтропия.

train_iris.py — цикл обучения 
mins, maxs = fit_normalizer(train_rows)       # только train!
S, Bv, Y = prepare(train_rows, mins, maxs, knots, classes)

model = KanClassifier(n_in=4, n_out=3, nbasis=G + K)
model.train(S, Bv, Y, epochs=3000, lr=0.02)

print(model.evaluate(St, Bt, Yt))

Не путайте 30/30 с «100% точностью»

Тридцать примеров — это маленькая выборка. Одна ошибка сдвинула бы оценку на 3.3 п.п., а другой split мог бы дать 28/30. Кросс-валидация (95.3% ± 2.7%) — более честная оценка обобщения. В отчётах и в демо мы приводим обе цифры, а не только красивую.

Модель уверенно разделяет setosa (он отделяется почти по ширине лепестка), а основные трудности — между versicolor и virginica. Это видно и в данных: их диапазоны перекрываются. Именно там кросс-валидация теряет свои 3–7%.

Что было бы с MLP

Маленький MLP 4 → 8 → 3 на Iris тоже даёт около 95–97% при аккуратной настройке. KAN здесь не «лучше вообще» — она компактнее и интерпретируемее: у каждого ребра можно нарисовать функцию и увидеть, как признак влияет на класс. Для учебного примера это важнее десятых долей процента.

Сохранение модели

Обученная модель — это не только код, но и числа. Мы сохраняем их в обычный JSON: его можно прочитать, проверить, передать и загрузить обратно без PyTorch.

export.py — веса в JSON 
payload = {
    "features": FEATURES,
    "classes": classes,
    "min": mins,
    "max": maxs,
    "knots": knots,
    "degree": K,
    "coef": model.coef,
    "base": model.base,
    "bias": model.bias,
    "metrics": {"test_accuracy": test_acc, ...},
}

with open("code/iris_model.json", "w", encoding="utf-8") as f:
    json.dump(payload, f, ensure_ascii=False, indent=2)

Почему JSON, а не pickle? JSON безопаснее (не исполняет код при загрузке), переносим между языками и удобен для чтения. Для больших моделей так хранить всё нерационально, но для компактной KAN это идеальный формат: наши веса занимают около 4 КБ.

Версионируйте модель

В JSON есть поля version и notes. Если вы меняете данные, нормализацию или архитектуру, сохраняйте новую версию. Иначе старый фронтенд может незаметно начать подавать признаки в другом порядке — и предсказания станут мусором.

Живое демо: модель в браузере

Сохранённых весов достаточно, чтобы предсказывать без Python. Страница demo.html загружает assets/iris_model.js — те же коэффициенты, что в JSON, — и считает B-сплайны, SiLU и softmax на JavaScript. Никакого сервера и интернета не нужно.

inference.js — как считается ответ 
function predict(values) {
    const xn = values.map(normalize);
    const basis = xn.map(x => basisRow(knots, degree, x));

    const logits = classes.map((_, k) => {
        let z = bias[k];
        for (let i = 0; i < features.length; i++) {
            z += base[k][i] * silu(xn[i]);
            for (let b = 0; b < coef[k][i].length; b++)
                z += coef[k][i][b] * basis[i][b];
        }
        return z;
    });

    return softmax(logits);
}

Именно этот код выполняется, когда вы двигаете ползунки на странице демо. Модель не «зашита» в if-else: это настоящая арифметика KAN с весами, полученными обучением.

Воспроизведение и ограничения

Всё можно повторить двумя командами. Первая запускает кросс-валидацию, вторая — финальное обучение и экспорт.

Время: около 12 секунд на CV и 6 секунд на финальное обучение на обычном CPU. Это важно: полный цикл «данные → модель → веса» укладывается в полминуты, поэтому экспериментировать можно быстро.

Что можно менять

  • Число эпох. Меньше — быстрее, но модель может не сойтись; больше — риск переобучения на 120 примерах.
  • Сетку G. Больше G — больше гибкости и параметров; на маленьком наборе это легко переобучает.
  • Seed. Другой split и инициализация дают другой результат; поэтому и нужна CV.
  • Признаки. Добавьте произведения или отношения размеров — и один слой KAN сможет учитывать взаимодействия.

Границы применимости

Модель обучена на 150 измерениях трёх видов ириса. Она не «понимает» ботанику, не работает с другими растениями и не является медицинской рекомендацией. Для реального применения нужны репрезентативные данные, внешний тест, мониторинг и понимание цены ошибки.

Упражнения

  1. Посчитайте число параметров KAN 4 → 3 при G = 3, k = 3.
  2. Почему в JSON нужно хранить min и max, а не только коэффициенты?
  3. Что произойдёт, если подать в демо ширину лепестка 5 см? Почему?
  4. Обучите модель с другим seed. Изменилась ли accuracy на тесте? Что это говорит о доверии к одной цифре?
  5. Предложите, как добавить в модель взаимодействие «длина × ширина лепестка», не переходя к глубокой сети.
  6. Почему 30/30 на тесте и 95.3% в CV — не противоречие?
Ответы и комментарии
  1. 3 · 4 · (3 + 3 + 1) + 3 = 84 + 3 = 87. Меньше G — меньше параметров, но и меньше гибкости.
  2. Без min/max невозможно правильно нормализовать новый вход. Одни коэффициенты описывают функцию на уже преобразованном [−1, 1]; масштаб — часть модели.
  3. Значение выйдет за обучающий диапазон; в демо ползунок ограничен, а сервис вернёт ошибку. Если насильно подать 5 см, KAN будет экстраполировать, и ответ станет ненадёжным.
  4. Скорее всего, accuracy изменится на 1–3 п.п. Именно поэтому одна цифра на одном split — не результат; нужны CV, несколько seed и отчёт о разбросе.
  5. Добавить признак x3 · x4 (или отношение) как пятый вход. KAN останется однослойной, но получит взаимодействие. Альтернатива — скрытый слой.
  6. На одном split из 30 примеров модель могла не ошибиться; CV проверяет пять разных разбиений и показывает среднее. Маленький тест просто менее информативен.

Итоги главы

  • KAN 4 → 3 с 111 параметрами — полноценная обучаемая модель, а не иллюстрация.
  • Один слой с softmax и кросс-энтропией обучается аналитическими градиентами и даёт 95.3% ± 2.7% в CV на Iris.
  • Веса можно сохранить в JSON и выполнять инференс на JavaScript — без Python и сервера.
  • Честная модель — это метрики, ограничения и модель-карточка, а не только accuracy.
