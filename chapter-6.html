Данные, признаки и честная оценка

Модель не бывает «умной» сама по себе. Она настолько хороша, насколько хороши данные и проверка. Здесь мы научимся собирать набор, делить его без утечек, выбирать метрики и не обманывать себя.

Все модели неверны, но некоторые полезны. Джордж Бокс

Перед главой

Достаточно уметь читать таблицу. Метрики, кросс-валидацию и утечки объясним с нуля; математика почти не понадобится. Это самая «бытовая» глава книги.

Из задачи — в данные

Обучение с учителем начинается с таблицы: в строках — примеры, в столбцах — признаки, и есть отдельный столбец с правильным ответом. Формально это набор пар D = {(xi, yi)}i=1N, где xi ∈ ℝd — вектор признаков, а yi — метка или число.

Мы будем работать с классическим набором Iris: 150 цветков, четыре измерения, три вида. Он маленький, но настоящий: в нём есть и разделимые классы, и трудные пограничные случаи. Этого достаточно, чтобы пройти весь путь до обученной модели и не ждать полчаса на CPU.

load_iris.py — читаем CSV без pandas 
import csv

FEATURES = ["sepal_length", "sepal_width", "petal_length", "petal_width"]

rows = []
with open("code/data/iris.csv", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        x = [float(row[name]) for name in FEATURES]
        rows.append((x, row["species"]))

print(len(rows), rows[0])   # 150 ([5.1, 3.5, 1.4, 0.2], 'setosa')

Почему не «просто все данные»

Если оценивать модель на тех же примерах, на которых она училась, вы измеряете память, а не обобщение. Нужны три части: обучение, валидация для выбора настроек и тест — только для финальной честной цифры.

Утечка данных

Утечка (data leakage) — это когда информация из теста случайно попадает в обучение. Самые частые виды: нормализация по всему набору до разделения, подбор гиперпараметров по тесту, дубликаты строк в разных частях выборки, использование будущих данных для предсказания прошлого.

Правило простое: всё, что зависит от данных, настраивается только на обучающей части. Средние, минимумы, максимумы, словари категорий — всё это фиксируется на train и затем применяется к val/test.

Подготовка признаков

KAN с B-сплайнами определён на отрезке [−1, 1], поэтому масштабирование входов — не украшение, а условие корректной работы. Самое простое преобразование — min-max:

x′ = −1 + 2 · x − mintrainmaxtrain − mintrain
Min-max в [−1, 1]. min и max считаются только по обучающей выборке.

Альтернатива — стандартизация x′ = (x − μ)/σ. Она не ограничивает диапазон, поэтому для KAN её обычно дополняют клиппингом или расширяют grid_range. Для Iris min-max удобнее: все четыре признака попадают ровно в рабочую область сплайнов.

normalizer.py — fit только на train 
def fit_normalizer(rows):
    mins = [min(r[0][i] for r in rows) for i in range(4)]
    maxs = [max(r[0][i] for r in rows) for i in range(4)]
    return mins, maxs

def normalize(x, mins, maxs):
    return [-1 + 2 * (x[i] - mins[i]) / (maxs[i] - mins[i])
            for i in range(len(x))]

Выход за диапазон

Если новый цветок имеет признак вне [mintrain, maxtrain], min-max выведет его за [−1, 1]. Для KAN это означает экстраполяцию: сплайн там не обучен. В сервисе такие входы нужно либо отклонять, либо явно ограничивать и предупреждать пользователя.

Метрики: что именно мы измеряем

Для классификации самая известная метрика — accuracy, доля правильных ответов. Но одна цифра почти всегда что-то скрывает. Начните с матрицы ошибок: строки — истинные классы, столбцы — предсказанные.

pred: setosapred: versicolorpred: virginica
true: setosa1000
true: versicolor091
true: virginica019

Здесь accuracy = 28/30 ≈ 0.933, но видно, что ошибки сосредоточены между versicolor и virginica — классами, которые действительно похожи. Для каждого класса считают precision и recall:

Precision = TPTP + FP,    Recall = TPTP + FN,    F1 = 2 · P · RP + R
Точность, полнота, F₁. Считаются для каждого класса, затем усредняются (macro).

Precision отвечает на вопрос «если модель сказала „versicolor“, как часто она права?». Recall — «какую долю настоящих versicolor она нашла?». F₁ — их гармоническое среднее, удобное, когда нужен баланс.

РегрессияMSE, RMSE, MAE, R²MSE чувствительна к выбросам
ВероятностиLog-loss (кросс-энтропия), калибровкаВысокая accuracy при плохих вероятностях

Всегда нужен baseline

Сравнивайте не с нулём, а с простым ориентиром: предсказание самого частого класса, логистическая регрессия, маленький MLP. Если KAN обыгрывает baseline на одном split — это ещё не результат; нужна кросс-валидация и несколько seed.

Кросс-валидация и протокол эксперимента

Один split из 150 примеров слишком шумный: одна ошибка на тесте из 30 меняет accuracy на 3.3 процентных пункта. Поэтому используют k-фолдовую кросс-валидацию: данные делят на k частей, по очереди каждую делают тестом, а остальные — обучением. Итог — среднее и разброс.

ACCCV = 1k Σj=1k ACCj   ±   std(ACC1..k)
Кросс-валидация. Среднее по фолдам и стандартное отклонение — честнее одной цифры.

Для классификации используют стратифицированные фолды: доли классов в каждом фолде сохраняются. Иначе может оказаться, что в одном тесте вообще нет редкого класса.

Подглядывание в тест

Если вы подбираете learning rate, число эпох и архитектуру по тесту, тест превращается в валидацию и перестаёт быть независимым. Его единственная задача — дать честную оценку уже выбранной модели.

Воспроизводимость начинается с фиксации seed, версии кода и параметров преобразований. В отчёте пишите не только accuracy, но и:

  • размер выборки и число классов;
  • метрику на train, CV и test;
  • разброс по фолдам или seed;
  • время обучения и инференса;
  • baseline, с которым сравниваете.

Iris: что известно до обучения

Прежде чем запускать KAN, посмотрим на данные. Четыре признака, 150 примеров, по 50 на класс. Простой baseline «всегда setosa» даёт 33.3% accuracy; «всегда самый частый класс» — тоже 33.3%, потому что классы сбалансированы.

Ширина чашелистика2.0 – 4.4Слабо разделяет versicolor и virginica

Наша обученная KAN 4 → 3 с 111 параметрами показывает 95.3% ± 2.7% в 5-фолдовой CV. На одном стратифицированном split 80/20 она дала 30/30, но это не «100% навсегда»: на другом разбиении результат будет ниже. Именно поэтому в книге и в демо мы приводим обе цифры.

Как читать такие числа

95% на Iris — это нормальный результат для модели с 111 параметрами. Он не означает, что модель «понимает ботанику». Он означает, что на этих четырёх измерениях и этом наборе данных она улавливает закономерность. Для реальной задачи нужны новые данные, проверка домена и отдельный разговор о рисках.

Упражнения

  1. Почему min/max для нормализации нельзя считать по всему набору, включая тест?
  2. По матрице ошибок из раздела 6.3 посчитайте precision, recall и F₁ для класса versicolor. Чему равна accuracy?
  3. Модель показала 30/30 на отложенной выборке из 30 примеров. Почему нельзя утверждать, что её точность равна 100%?
  4. Какой baseline разумно взять для Iris и какой результат считать «лучше случайного»?
  5. Приведите три примера утечки данных, которых не было в тексте.
  6. Зачем нужны и валидация, и тест? Можно ли обойтись одним?
  7. Какие метрики выбрать, если классы сильно несбалансированы?
Ответы и комментарии
  1. Потому что тогда параметры преобразования «увидят» тест. Это утечка: модель косвенно получает информацию о распределении тестовых данных. min/max фиксируются на train и применяются к остальным частям.
  2. Для versicolor: TP = 9, FP = 1 (virginica, названная versicolor), FN = 1 (versicolor, названный virginica). Precision = 9/10 = 0.9, recall = 9/10 = 0.9, F₁ = 0.9. Accuracy = 28/30 ≈ 0.933.
  3. Тридцать примеров — маленькая выборка; одна ошибка сдвигает оценку на 3.3 п.п. Кроме того, это один конкретный split. Нужны кросс-валидация, несколько seed и, в идеале, внешний тест.
  4. «Всегда самый частый класс» даёт 33.3%. Разумный ориентир — заметно выше 33% и выше простой логистической регрессии; на Iris 90–96% уже хороший результат для компактной модели.
  5. Например: заполнение пропусков средним по всему набору; отбор признаков по корреляции со всей меткой; дубликаты одного и того же объекта в train и test; использование будущих продаж для прогноза прошлых.
  6. Валидация нужна для выбора настроек и ранней остановки, тест — для финальной независимой оценки. Если настраивать по тесту, он перестаёт быть независимым, и оценка завышается.
  7. Accuracy может быть высокой при бесполезной модели. Нужны precision/recall/F₁ по классам, balanced accuracy, ROC-AUC или PR-AUC в зависимости от задачи и цены ошибок.

Итоги главы

  • Данные — это таблица «примеры × признаки + метка»; качество модели ограничено качеством данных и протокола проверки.
  • Нормализация и любые преобразования настраиваются только на train; иначе возникает утечка.
  • Accuracy — лишь одна метрика; матрица ошибок, precision, recall и F₁ показывают, где именно модель ошибается.
  • Кросс-валидация и несколько seed дают честную оценку с разбросом; тест смотрят один раз.
  • Iris — маленький, но настоящий набор: baseline 33.3%, наша KAN даёт 95.3% ± 2.7% в CV.
